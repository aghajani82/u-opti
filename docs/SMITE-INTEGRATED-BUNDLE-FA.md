# بسته بازبینی نصب U-OPTI × Smite — HOLD_WITH_BLOCKERS

این بسته برای Ubuntu 24.04 و میزبان‌های آزمایشی amd64 با نام `ir` و `kh` است.
نسخه تولیدی، انتشار امضاشده یا تأیید موفقیت FRP/WSS/XHTTP نیست.
روی Grandoptical اجرا نشود. در مأموریت ساخت این بسته هیچ سروری تغییر نکرده است.

## محتویات و منشأ

نسخه دقیق هر سورس و هش ایمیج‌ها در `VERSIONS.json` است؛ تمام فایل‌ها در
`SHA256SUMS` ثبت شده‌اند. SHA256 کل ZIP باید ابتدا با مقدار گزارش تحویل مقایسه شود.
این checksum برای تشخیص تغییر بایت‌هاست، نه جایگزین امضای انتشار.

- `u-opti/`: سورس کامل Commit ثابت main، نصب‌کننده و تمام ماژول‌ها.
- `Smite-current-source/`: سورس بررسی‌شده فعلی؛ با سورس ایمیج قدیمی یکی فرض نشود.
- `Smite-stage15-build-source/`: سورس دقیق `4e16633a304db6c03f7f2911cc7d77213b0c4ec1` که ایمیج‌ها از آن ساخته شده‌اند.
- `images/`: هر دو ایمیج Stage15 و Manifest اصلی، بدون بازسازی یا تغییر ID.
- `dependencies/`: آرشیو رسمی FRP 0.71.0 برای amd64 و arm64، با بررسی مستقل هش و هر دو ELF.
  وجود آرشیو arm64 به معنای وجود ایمیج Stage15 arm64 نیست؛ نصب این بسته فقط amd64 است.
- `start.sh`: ورود به همان ویزارد Clean-RC؛ FRP یا تانل را خودکار فعال نمی‌کند.

ZIP اصلیِ دریافت‌شده از GitHub، Artifact شماره `12714389112`، فقط سه فایل ایمیج/Manifest داشت؛
نصب‌کننده نبود. ZIP پیوست کاربر در نشست قابل دریافت نبود؛ تطبیق با آن انجام نشده است.
هش ZIP اصلی GitHub:
`2bda0c80aa77ce6fa6bd1af0a4ed0d8fccfad670915dfd2f56a6120b08d19a71`.

## وابستگی‌ها و محدودیت نصب

این یک توزیع کاملاً آفلاین Ubuntu نیست. نصب‌کننده اصلی سورس را از GitHub با همان SHA ثابت
دریافت می‌کند؛ apt، Docker Engine و Compose plugin، Nginx/Certbot و نصب/ایمیج Sanaei
هنوز به شبکه و مخازن مربوط وابسته‌اند و داخل ZIP نیستند. بسته این محدودیت را پنهان نمی‌کند.
گواهی TLS، دامنه، IP واقعی IR/KH و انتخاب Instance سنایی ورودی اپراتور هستند.
اطلاعات هویت و Pairing Code باید روی همان میزبان تولید شوند؛ هیچ هویت واقعی یا Backup سروری
داخل بسته قرار ندارد. داده‌های آزمایشی موجود در سورس tests فقط Fixture عمومی مخزن هستند.

## ترتیب اجرای بعدی — فقط بعد از مجوز تست زنده

**BOTH**: Snapshot جدید، دسترسی کنسول و Backup محافظت‌شده بگیرید. ZIP را در مسیر خصوصی
root استخراج کنید؛ پیش از اجرای هیچ فایل، SHA256 کل ZIP را با گزارش تحویل مطابقت دهید.
سپس در پوشه بسته `sha256sum --check --strict SHA256SUMS` را اجرا کنید.

اگر U-OPTI قبلاً نصب شده است، ابتدا با SHA داخل `VERSIONS.json`، از گزینه Update U-OPTI
به همان نسخه بروید؛ فقط تنظیم متغیر Branch، سورس نصب‌شده را آپدیت نمی‌کند.
نصب تازه را روی state موجود Smite تکرار نکنید؛ ویزارد باید آن را رد کند.

**IR — نصب تازه روی میزبان بازسازی‌شده**:

```bash
bash start.sh IR
```

1. گزینه نصب Panel + Iran Node؛ نام پنل واقعی و `node-ir` را وارد کنید.
2. HTTPS/443 و حساب مدیر را از ویزارد تکمیل کنید.
3. از `u-opti --smite-pairing`، رزرو/کد یک‌بارمصرف و فعال‌سازی Signed ایران را طبق
   راهنمای `u-opti/docs/SMITE-STAGE15-KH-INSTALL.md` انجام دهید.
4. ابتدا Healthy، Signed و Connected بودن `node-ir` را تأیید کنید. نصب تازه روی IR فعلی لازم نیست.

**KH — نصب تازه**:

```bash
bash start.sh KH
```

1. گزینه ۲: Foreign Node؛ پنل `02ir.kolbe1.ir`، دامنه واقعی KH و `node-kh`.
2. گزینه ۴: نصب/انتخاب Sanaei و اتصال پایگاه آن فقط‌خواندنی؛ این مرحله پیش از Redeem انجام شود.
3. گزینه ۶: Gateway HTTPS/443، TLS معتبر و Allowlist آدرس واقعی IR؛ Control URL تولیدشده را نگه دارید.
4. **IR**: در پنل، `node-kh` را در Signed Mode رزرو کنید؛ UUID را ثبت کنید.
   در ویزارد Pairing گزینه ۸، همان UUID، نام و Control URL دقیق را تأیید کنید؛ سپس کد یک‌بارمصرف بسازید.
5. **KH**: `u-opti --smite-pairing`، گزینه ۳ Redeem و سپس گزینه ۷ فعال‌سازی Signed.
6. Healthy، Connected، HMAC در هر دو جهت و Replay PASS لازم است. هیچ تغییر دستی Compose مجاز نیست.

برای IR موجود، این ایمیج پنل جهت Signed Pairing نود KH نیازمند تعویض نیست.
اما سورس جدیدِ رفع نشت Token در مسیر FRPS پنل، داخل ایمیج Stage15 قدیمی وجود ندارد.
برای استفاده از آن مسیر FRPS، ساخت مستقل ایمیج جدید، پذیرش ID و طرح ارتقای Backup/Rollback
لازم است؛ این بسته آن ارتقا را خودکار اجرا یا تأیید نمی‌کند.

## FRP، WSS و XHTTP — توقف فعلی

FRP داخلی ایمیج Stage15 نسخه 0.65.0 است؛ وجود آن به معنای پذیرش FRP مدیریت‌شده نیست.
آرشیوهای 0.71.0 این بسته بررسی شده‌اند، اما صرف وجود باینری نیز مجوز نصب/فعال‌سازی نیست.
کمک‌برنامه Host Executor آزمایشی است و عمداً به گزینه نصب عمومی ویزارد وصل نشده است.
هیچ دستور جایگزینی Digest، ویرایش دستی Compose، فعال‌کردن دستی WSS یا بازکردن 7000/8888 ارائه نمی‌شود.

موارد باقیمانده که مانع «نصب کامل نهایی» هستند:

1. پذیرش و تراکنش مستقل Stage15 WSS/443، Edge و Owner/Child، همراه Rollback و بازیابی.
2. ساخت و بررسی ایمیج دارای اصلاح محرمانگی FRPS؛ ایمیج قدیمی نباید با برچسب جدید پذیرفته شود.
3. آزمون واقعی دو میزبان: Signed Owner، FRP/WSS، اتصال XHTTP کلاینت، reboot و Rollback.
4. قطع برق واقعی وسط نوشتن فایل می‌تواند به‌جای بازیابی خودکار، به HOLD و بررسی کنسول نیاز داشته باشد.
   تست checkpoint شبیه‌سازی‌شده را معادل اثبات همه قطع‌های احتمالی برق ندانید.

پس از رفع این موانع، ترتیب تانل باید Owner معتبر → Shared Child → Inbound سنایی روی
`127.0.0.1` با پورت و XHTTP Path انتخاب‌شده → خواندن Signed Inventory → تأیید Root Grant
→ انتشار مسیر Nginx روی 443 باشد. این بند دستور فعال‌سازی فعلی نیست.
پورت و Path سنایی و Grant اپراتور هنوز دستی‌اند؛ کشف Inventory و اعتبارسنجی Signed Intent
در مسیر موجود خودکار هستند. Backhaul/Rathole نباید با نصب FRP تغییر کنند.

## وضعیت پذیرش

- نتایج دقیق CI و SHA نهایی: گزارش تحویل و GitHub Actions همان Commit.
- تست‌های محلی Host Executor: فایل‌سیستم واقعی موقت، Docker و Signed callbacks شبیه‌سازی‌شده.
- Docker/Compose واقعی: فقط تست ایزوله GitHub Actions؛ نه نصب سیستم‌عامل کامل و نه IR/KH واقعی.
- اتصال واقعی FRP/WSS/XHTTP و reboot دو سرور: **انجام‌نشده**.
- نصب کامل یک‌مرحله‌ای FRP از ویزارد و انتشار تولیدی: **تأییدنشده — HOLD**.
